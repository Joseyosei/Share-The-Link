# Stage 08.01 — Private Ollama pilot
Account commands for links, profile, analytics and digital products use authenticated account queries without model requests or quota. Commands do not mutate data. General generation is single-turn, not autonomous agent execution. No external model required for account commands.
## Pilot setup
Use separate staging Supabase and apply all preceding migrations and 20261126190000_local_ai_queue.sql. Set LOCAL_AI_ENABLED=true, LOCAL_AI_PILOT_USER_ID to the authenticated pilot's Supabase UUID, LOCAL_AI_WORKER_SECRET to a unique random 64-character hex secret (openssl rand -hex 32). Keep server-only; never use VITE_ or share secrets. Configure the same worker secret on the trusted Mac using local shell env (read -s or secure local config). No public port forwarding, no Supabase service key on Mac. Cloud provider remains optional. Existing quota and Stripe verification still required for generation. Only one pilot account; never use founder-owned workstation to process unrelated customers' data without proper security and privacy review.
Install Ollama from https://ollama.com/download, Node 22+. Run ollama pull qwen3:4b; use qwen3:8b if enough memory, or gemma3:4b. Start Ollama app. Clone this branch and set STL_APP_URL to exact HTTPS preview origin, LOCAL_AI_WORKER_SECRET in local shell, optionally OLLAMA_MODEL. Run node scripts/ollama-worker.mjs. Preview must be accessible to worker via normal authorized network access; Vercel deployment protection can block it; use an approved staging configuration, not disabling production security. No secrets in code. Worker sends outbound HTTPS to application, only model calls go to loopback 127.0.0.1. Stop with Ctrl+C. Keep Mac awake while processing. Idle polling every 20 seconds; run only during pilot to minimise hosting usage. 
## Workflow
Open STL AI Assistant. Account commands remain usable even if AI disabled or quota unavailable. Select Local Ollama, consent, generate. One pending job per pilot, atomic worker claim, random lease, 5-minute expiry. Worker clears prompts on completion; expired rows deleted on next claim/enqueue; schedule cleanup before production to guarantee retention. Browser polls with timeout. No automatic fallback to cloud, no retry on failed model result. Quota counts accepted attempts; concurrent enqueue failure can count an attempt. Failed/expired jobs don't auto-retry. Only validated JSON drafts; publishing remains separate. 
## Limitations
No physical Mac access or installed Ollama verified. Real local generation, staging RLS, queue concurrency, worker disconnection, auth, quota and browser tests outstanding. Worker only single-account pilot, not production multi-tenant hosting. Hardware, power and hosting requests have costs even with no per-token bill. No marketing messages sent or live account edits. Production branch still requires separate targeted bot hotfix or reviewed staged release.
