# Sign in with Apple (Stage 08.02)
Feature flag VITE_APPLE_AUTH_ENABLED defaults off. Email/password unchanged; Google not restored. Dedicated PKCE callback /auth/apple/callback, one explicit exchange, allowlisted destination. Both sign-in and sign-up start the same Supabase Apple OAuth flow. Existing profiles are not overwritten. Apple may supply a relay email and no name; verify live new-user trigger and apply Apple profile provisioning migration to staging before activation. Review username length constraints and existing triggers, test collisions. Do not apply unreviewed SQL to production.
## Apple Developer
Active membership, primary App ID with Sign in with Apple capability, associated Services ID (proposed app.sharethelink.web), website host sharethelink.app and Supabase Auth host, exact return URL shown in Supabase Auth > Providers > Apple (https://PROJECT_REF.supabase.co/auth/v1/callback unless custom Auth domain). Create private key associated with primary app, note Team ID and Key ID. Generate ES256 client secret JWT using Supabase official guide, with Services ID as subject; secret expires at most 6 months. Never commit or share .p8 or JWT; enter secret in Supabase only. Register email sources for Apple's Private Email Relay and verify SPF/DKIM as appropriate.
## Supabase
Enable Apple provider with Services ID as first client ID, generated client secret. Set Site URL to https://sharethelink.app; allow exact callback URLs https://sharethelink.app/auth/apple/callback?next=%2Fdashboard and https://sharethelink.app/auth/apple/callback?next=%2Fpricing (plus exact staging equivalents). Verify redirect matching using the Supabase console and test actual redirect. No wildcard production preview domains. Review identity linking and private email behavior; never merge accounts by unverified email. User chooses a public username/display name in dashboard settings; no private relay prefix published by proposed trigger. Real profile provisioning, RLS, duplicate/new account and linking tests required.
## Release
Test on isolated staging with real Apple test sign-in, cancellation, refresh, password recovery, existing email account, hide-my-email, username collision, private relay mail and mobile/desktop browsers. Set flag in staging first, then production after tests. Do not enable without validated config. Schedule secret rotation before expiration. Native iOS implementation separate. Review Apple's account deletion and revocation requirements before native app release.
