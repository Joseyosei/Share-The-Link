# Stage 05 — Digital commerce (test-only)
Open /connect > Digital commerce; public shop at /shop/:username. Existing external listings and legacy Stripe stores remain separate. Create a PDF draft (10 MB), optionally add a reusable product-specific percentage code, publish or unpublish. Checkout uses direct charges on a verified Stripe test connected account with user_id and commerce=test metadata; no platform fee in this stage. GBP only; one product per checkout. Orders show latest 100 test orders and gross paid amounts, not actual payouts or net revenue. Customer email from verified Stripe Checkout.
## Setup (staging only)
Apply earlier migrations first and then 20261126140000_digital_commerce.sql to a separate staging project. Review storage policies; verify direct public and cross-user access denied. Use test-mode Stripe key. The test seller setup button creates or resumes a GB Express test account in a separate service-role-only mapping table; it does not overwrite existing live connected accounts. Complete test onboarding. Other countries are not supported by this initial seller setup. Configure a Connect event destination for /api/webhooks/stripe with STRIPE_CONNECT_WEBHOOK_SECRET (distinct from platform webhook), events checkout.session.completed, checkout.session.async_payment_succeeded, checkout.session.expired, charge.refunded, charge.dispute.created. Set COMMERCE_APP_URL to trusted HTTPS staging origin; set COMMERCE_CHECKOUT_ENABLED=true only after tests. Live keys can never enable this path. No paid plan changes, no actual payments, no production migration applied.
## Delivery
Opaque random order claim key in success URL fragment, SHA-256 digest only in DB. Keep private order link. Server checks session, amount, currency, connected account, payment intent and refund/dispute status before issuing 60-second signed download URL. Signed URLs remain valid until expiry; downloaded copies cannot be revoked. Webhooks reconcile paid orders idempotently. No receipt email or lost-link recovery implemented yet; add authenticated recovery/transactional email before live release. Stripe receipts depend on account settings. Uploaded files are immutable to users. Orphan file cleanup, content/malware scanning, tax/VAT, refund workflow, monitoring and production legal review are release blockers. Do not advertise or enable live selling until completed.
## Verify
Run CI and build. Apply migrations in staging. Test seller account ownership, public catalogue redaction, cross-account order access, invalid code, duplicate webhook, failure/cancellation, refunded/disputed download refusal, upload size/type, RLS, link expiration, mobile and checkout return. Verify app origin matches preview; use Stripe test cards only. This is a foundation, not a production payment certification.
